# Hôtel : une demande d’accès n’est pas un séjour en difficulté

Après avoir corrigé un [message pré-arrivée](/articles/message-pre-arrivee-hotel/), une équipe peut recevoir moins de questions sur l’entrée. Mais compter les messages ne dit pas combien de séjours ont été concernés, ni si la correction en est la cause. Cette fiche propose un **registre hebdomadaire de rapprochement**, complémentaire de notre [tri des demandes et incidents](/articles/demande-incident-satisfaction-denominateurs/) : elle suit l’accès, pas la satisfaction déclarée.

## Trois unités à ne pas fusionner

1. **Sollicitations d’accès reçues** : appels, courriels ou messages demandant comment entrer. Deux relances d’un même séjour comptent ici deux fois. Écarter les demandes sans rapport avec l’accès.
2. **Séjours distincts avec au moins une demande d’accès** : rapprocher les sollicitations d’un identifiant interne de séjour, sans le publier dans le tableau partagé. Une demande impossible à rapprocher reste « non attribuée », pas un nouveau séjour présumé.
3. **Séjours commencés pendant la période** : dénominateur tiré du registre de l’établissement, selon une définition fixée avant le suivi. Rattacher les demandes à la **semaine d’arrivée du séjour**, même si le message a été reçu la semaine précédente ; sinon numérateur et dénominateur ne portent pas sur la même cohorte. Ce nombre inclut les séjours sans demande ; il n’est ni le nombre de messages envoyés ni celui des personnes hébergées.

Garder les demandes **avant** et **après** l’arrivée séparées si l’on veut examiner une consigne pré-arrivée. Un appel pendant le séjour ne prouve pas que le message était défaillant. Une question n’est pas non plus un incident d’entrée bloquée.

## Tableau rempli : deux semaines entièrement fictives

Le [CSV](/assets/suivi-demandes-acces-hotel.csv) contient deux lignes inventées et une ligne vierge. « Semaine A/B » désigne la semaine **d’arrivée**, non celle de réception du contact. Les nombres n’ont été observés dans aucun hôtel ; ils servent seulement à vérifier les calculs.

En A, **7 sollicitations pour 80 séjours commencés** = 8,75 sollicitations pour 100 séjours ; **5 séjours distincts sur 80** = 6,25 % des séjours concernés. En B, les deux lectures donnent **4/84 = 4,76** (arrondi). Elles coïncident en B uniquement parce qu’aucun séjour n’a relancé dans cet exemple. Le premier indicateur est une charge de contact, pas une part de clientèle ; il pourrait dépasser 100 pour 100 séjours.

## Retester sans attribuer une baisse imaginaire

Avant de comparer, garder le même lieu, les mêmes canaux et la même fenêtre « avant arrivée ». Vérifier le volume de séjours, la part d’arrivées tardives, les horaires de réception et le mode d’envoi pour chaque cohorte. Documenter la version du message **réellement envoyée**, pas seulement le brouillon. Si les canaux ou le rapprochement changent, présenter les comptes séparément plutôt qu’une évolution trompeuse. Une demande non attribuée reste dans un compte séparé et ne rentre pas dans le taux par séjour.

Relever quelques questions récurrentes **sans donnée personnelle** : entrée introuvable, code non reçu, contact de secours indisponible. Rejouer le scénario à l’heure concernée, corriger la consigne si l’écart est constaté, puis continuer le suivi. La baisse fictive de 7 à 4 sollicitations ne démontre ni effet causal du message, ni amélioration de satisfaction, ni fréquence pour d’autres hôtels. Ne publier ni identité de voyageur, ni numéro de chambre, ni code d’accès dans la fiche.
